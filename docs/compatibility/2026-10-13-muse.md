# Muse Code compatibility — 2026-10-13

Built-in `muse` support is implemented and installed locally. Existing compatibility fixes remain intact; AGY remains the only built-in Google target. This report records pre-release verification.

## Native contract

Tested Muse Code 1.4.7 (`1.4.7-R6101.1`) on macOS arm64. The installed launcher initially reported 1.4.6 and auto-updated during discovery. Subsequent native probes set `MUSE_NO_AUTO_UPDATE=1`; no intentional upgrade or authentication/configuration command was run.

- `muse exec` rejects missing prompt text rather than reading stdin. A positional `-` is literal. `--prompt-file /dev/stdin` fails with `is not a regular file`.
- yoyo stages the complete rendered prompt in a private per-call temporary directory, passes the regular file to `--prompt-file`, and sends empty stdin. Cleanup runs after success, failure, and timeout. Custom command prefixes, model IDs, and native argument passthrough are preserved.
- Workers use `--trust-workspace --disable-approval`, retaining Muse's default sandbox. Reviews use `--disable-write --disable-shell` and `run.toolset=["read_file","search"]`; shell, write, MCP, and subagent tools are not selected. Guessed `read-only`/`readonly` profile IDs were unavailable, so the adapter does not depend on them.
- Calls use `--no-session-log`; yoyo keeps its own ledger and captures. Named yoyo sessions are rejected until native mapping is implemented. Native text output can remain quiet across tool/model steps, so background/wait is the supported polling recipe.

Primary sources checked today: [Muse Code](https://dev.meta.ai/docs/muse-code), [headless runs and skills](https://dev.meta.ai/docs/muse-code/extending), [permissions](https://dev.meta.ai/docs/muse-code/permissions), [configuration](https://dev.meta.ai/docs/muse-code/configuration), and the installed CLI's native help.

## Caller discovery and sandbox limit

Muse discovers shared user skills and now receives native copies under `$XDG_CONFIG_HOME/muse/skills`, defaulting to `~/.config/muse/skills`. The native copy remains available when foreign personal context is disabled.

Caller run `20261013T091715-b703e9a4`, with foreign personal context disabled, reported loading the native yoyo skill and launched one real read-only Codex child. The child's recorded command, mode, failure, and unchanged seed were independently inspected. The parent polled and diagnosed the failure; it did not save a fabricated answer or report success.

Child `20261013T091737-ecec0ed4` exited 1 before answering:

```text
WARNING: proceeding, even though we could not create PATH aliases: Operation not permitted (os error 1)
Error: failed to initialize in-process app-server client: Operation not permitted (os error 1)
```

Control run `20261013T092140-6a4927ac` used the same workspace and seed outside the Muse parent sandbox, retained Codex's read-only sandbox, and completed in 24.308 seconds. It returned the correct seed text, omitting the trailing newline. A later direct probe confirmed that Muse's sandbox denies read/write opening of `~/.codex/installation_id` and nested Seatbelt setup; local socket-pair creation succeeds. The exact syscall behind Codex's app-server error remains untraced. See [the sandbox diagnosis and native YOLO controls](2026-10-13-muse-sandbox.md).

Successful Muse-to-Codex nested delegation remains unverified under Muse's default sandbox. yoyo does not weaken that sandbox or persist a different native policy. Configured native hooks also run outside Muse's tool sandbox; the read-only flags are not isolation from those hooks.
